03 — Capstone

AMS-RAG: one agent, three data stores

A unified, agent-routed RAG framework that treats vector, relational and graph stores as specialised tools instead of a single monolithic index.

Real organisational data is heterogeneous — unstructured reports, structured tables, and relationship-heavy records. Traditional RAG flattens all of it into one vector index and loses precision. AMS-RAG instead puts an orchestrator agent in front of three purpose-built pipelines and lets it decide which one to call.

The reference deployment is a Home Team Unified Agent over three public-sector datasets — Singapore Police Force, Singapore Prison Service and HTX — with role-based access control layered on top, so an officer and a director asking the same question see different authorised scopes.

Repository Python 3.11+ · LlamaIndex · Docker Compose

The four moving parts

A LlamaIndex agent workflow acting as “Chief Data Orchestrator”.

  • Classifies intent into crime/scams, inmate statistics or project relationships, then executes the matching tool.
  • Tool surface is filtered by the signed-in user's rank, so unauthorised stores are never callable.
  • Implemented in Agent/agent.py, with a Streamlit auth and chat UI in Agent/app.py.

LlamaIndex AgentWorkflowTransformersStreamlit

Unstructured text and visual data — SPF Annual Crime Reports.

  • Nanonets OCR parses complex PDF layouts and tables into markdown before chunking.
  • Embeddings from multilingual-e5-large stored in ChromaDB.
  • Hybrid retrieval pairs semantic similarity with BM25 keyword search.
  • Results re-ranked by BGE-Reranker-v2-m3 and expanded with HyDE for better context relevance.

ChromaDBNanonets OCRBM25HyDECross-encoder rerank

Precise lookup and aggregation — SPS inmate statistics.

  • CSVs normalised into PostgreSQL and queried through a text-to-SQL engine.
  • Llama-3.1-8B-Instruct served locally through vLLM generates the SQL.
  • Query-Time Table Retrieval selects only relevant schemas first, cutting tokens and hallucination risk.

PostgreSQLText-to-SQLvLLMQTTR

Multi-hop reasoning and relationship discovery — HTX annual report.

  • Property graph built in Neo4j via PropertyGraphIndex.
  • Text-to-Cypher generation traverses relationships such as projects to departments.
  • Entity disambiguation and schema-aware prompting keep generated Cypher grounded; a regex sanitiser guarantees it executes.

Neo4jText-to-CypherPropertyGraphIndexEntity disambiguation

Every iteration — base, advanced, refactored, agent — was evaluated with a pipeline-appropriate metric set.

Benchmarks were run across five served models — Llama 3.1 / 3.2, Ministral 3, Qwen3 4B and 8B, plus a fine-tuned and chain-of-thought variant — and compared against Microsoft GraphRAG and Arctic-Text2SQL-R1-7B baselines. Results are committed alongside the code.
